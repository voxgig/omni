# Code review — omni (2026-08)

A full review of the runner and its 23 ports. omni is a test runner, so a bug
here **hides bugs** in everything it tests — leniency, not crashes, is the
operative risk. Findings were checked against source; those marked *(reproduced)*
were verified by compiling and running the code.

Companion review of the sibling project is in `voxgig/sekreto`
(`doc/design/review-2026-08.md`); the two share a root cause (hand-rolled parsers
without depth limits or a shared edge-case corpus).

## Overall

The core is strong: exact `out` comparison (`deepequal`) rejects every coercion
trap, absent-vs-null is carried by a real ABSENT marker in every port, and all
audited ports carry genuine can-go-red negative tests. The weaknesses are (1) the
`match` partial-matcher, which has several false-pass paths, (2) the hand-rolled
JSON parsers, which diverge between ports and crash on deep input, and (3) the
parity net (`check_parity.py`), which checks names, not behaviour.

## High

### OM-1 — The `match` partial-matcher has several false-pass paths *(reproduced)*
`typescript/src/Runner.ts` `matchval` / `typescript/src/Util.ts` `jsonstr`.

- An absent value stringifies to the literal `"undefined"` (`Util.ts`, `jsonstr`)
  and is then substring-tested, so a **typo'd match key passes**:
  `match:{out:{labell:"fine"}}` against `{label:"x"}` → PASS (`"fine"`, `"un"`,
  `""` are substrings of "undefined"). Converts "field missing" into "matches".
- `__UNDEF__` and `__NULL__` both fold to `null` in `matchval`, then
  `null == base || NULLMARK === base` — so `__UNDEF__` matches present-null and
  `__NULL__` matches absent. This collapses exactly the distinction AGENTS.md says
  never to collapse.
- Empty containers assert nothing: `match:{}` passes any result; `match:{out:{}}`
  passes `12345`.
- String leaves match the *serialized* value, including map **keys** and numbers:
  `match:{out:"even"}` passes `{even:false}`; `match:{out:"5"}` passes `55`;
  `match:{out:""}` passes anything.

Exact `out`/`deepequal` is unaffected; the leniency is confined to `match`. Fix in
canonical, add `spec/fib.json` counter-cases, propagate to all ports.

### OM-2 — Hand-rolled JSON parsers diverge between ports and crash on depth *(reproduced)*
The whole point of omni is that the ports agree; the in-tree parsers don't.
- **C** (`c/src/json.c`) parses numbers with `strtod(text,NULL)` ignoring the end
  pointer → silently wrong values: `[1-2]` → `[1]`, no error. Unique to C.
- **Haskell** accepts trailing commas and resolves duplicate keys first-wins;
  **OCaml** is also first-wins. Canonical (and Rust/C/Lua/Zig) are last-wins.
- All five hand-rolled parsers mishandle surrogate-pair `\uXXXX` escapes, each
  differently.
- No depth limit anywhere: deep nesting → C **segfault**, Rust **abort**, others
  catchable. Canonical throws a catchable `RangeError`.

Fix: align to canonical semantics (last-wins, strict number tokenization, reject
trailing commas, correct surrogate combining) and add depth limits. Zig is exempt
(uses `std.json`).

## Medium

### OM-3 — `check_parity.py` verifies names, not behaviour
`tools/check_parity.py` `defined()` runs `re.findall` over raw source, matching
identifiers inside comments and strings, with zero semantic checking. A port whose
`deepequal` was `return true` passes `make parity`. DOCS.md §9's claim that fib.json
"proves" match-rule parity is overstated.

### OM-4 — Real port divergences fib.json cannot see
All in areas the spec never exercises: Swift `errify` hardcodes `name:"Error"` (so
`err.name` matching fails); Swift/Elixir/Clojure never attach `client` to the `ctx`
argument; NaN deep-equality diverges (Python/Ruby/PHP/Clojure); Go flag coercion is
internally inconsistent; error-capture scope is narrower in Go/Java/Swift/Elixir/
Clojure. Add fib.json entries pinning `err.name` and a `ctx`+client group.

### OM-5 — Regex: catastrophic backtracking; count-overflow crashes
All in-tree engines are the same un-memoized CPS backtracker (Lua **62 s** for 22
chars). Zig `{n}` parsing overflows `usize` → Debug panic; OCaml's `{n}` raises a
`Failure` that escapes its handler. C's POSIX bridge silently drops `(?:...)`.

## Low / informational
Empty `set` passes vacuously; error matching is message-substring only; `__proto__`
in a spec evaporates in `clone` (safe, but the clone loses the key → vacuous match);
non-plain objects collapse to `{}`; C drops NUL; number leniency (`+5`,`01`,`.5`) is
accepted by all hand-rolled parsers (mutually consistent).

## Confirmed strengths
- `deepequal` (exact `out`) is excellent: `5≠"5"`, `true≠1`, `[]≠{}`, extra keys
  rejected, `null≠undefined`, NaN handled.
- Absent-vs-null carried by a real ABSENT marker in every audited port.
- The four required negative tests genuinely go red in all audited ports.
- Go/Python/Ruby/PHP/Java runners are line-for-line faithful to canonical.
- Spec parsing uses strict `JSON.parse`; the runner rethrows its own `OmniError`
  as a failure, so it can't fake an `err` pass.
